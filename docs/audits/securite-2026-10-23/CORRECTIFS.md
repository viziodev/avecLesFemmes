## Migrations et expérience

- **015_trusted_devices.sql** : preuve d’appareil hachée, clé d’enveloppement dédiée, expiration et index.
- **016_revoke_legacy_pwa_sessions.sql** : révocation des anciennes sessions PWA, susceptibles d’avoir été obtenues par code seul ; mots de passe, données métier et sessions Super Admin conservés.
- Première autorisation d’un appareil : identifiant et mot de passe initial, puis code secret. Pour un ancien coffre, le mot de passe initial est nécessaire à la migration conservant les brouillons. Une erreur de récupération conserve le coffre et signale l’indisponibilité hors ligne.
- Réouvertures en ligne sur appareil autorisé : code secret. Après expiration/révocation de la preuve : « Reconnecter cet appareil avec le mot de passe initial ». Oublier l’appareil exige un acquittement serveur.
- Hors ligne : mot de passe initial de 12 caractères minimum, consultation des données préparées et saisies en attente. Au retour du réseau, synchronisation explicite avec contrôles serveur et idempotence.
- Si une coupure intervient pendant une confirmation par code, le code n’autorise pas une conversion silencieuse en brouillon. Vérifier l’état de la saisie puis la confirmer hors ligne par mot de passe.
- Les anciens accès dont le mot de passe initial était un PIN court ne peuvent plus ouvrir un nouvel appareil. Une récupération d’identité vérifiée est nécessaire. Cette livraison ne fournit pas de récupération automatique d’un mot de passe initial perdu.

## Validation

- **43 tests API métier et migrations réussis** : dont révocation des anciennes sessions et conservation des mots de passe.
- **9 régressions de sécurité API réussies**, sur base PGlite en mémoire avec identités fictives et configuration de production. Les cookies Secure/HttpOnly/Strict y sont contrôlés sans les exporter dans les preuves.
- **3 tests navigateur de sécurité réussis**, puis **3/3 sur le conteneur unique Render local** : protections HTTP, refus du déchiffrement par PIN et migration des coffres conservant les brouillons.
- **104/104 parcours mobiles réussis** sur Chromium et WebKit, en 4,1 minutes : interfaces des deux profils, confirmation, récupération, verrouillage, oubli d’appareil, brouillons et synchronisation. Les 30 scénarios ajustés ont aussi été validés séparément. [Validation](../../VALIDATION.md).
- **Qualification PostgreSQL 18 réussie** : 1 001 groupements, 201 201 adhésions/participations et cotisations fictives ; droits RLS, idempotence concurrente, totaux rapprochés et huit tentatives d’authentification simultanées. Aucun accès à Neon ou à une base de production. [Rapport](../../recette/qualification/securite-0260.json).
- **Parcours E2E réel réussi sur Compose et sur le conteneur Render local** : création d’un compte fictif avec mot de passe initial fort, choix de code et affichage du QR. Ce contrôle ciblé ne constitue pas une exécution de toute la suite E2E historique.
- Versions cohérentes 0.26.0, typecheck, constructions Docker API/web/PWA et Render, format et tests de version/livraison/mise à jour contrôlés. Aucun déploiement distant réalisé.

Preuves : [API](preuves-apres/api.json), [HTTP local](preuves-apres/http-headers.json), [coffre](preuves-apres/offline-counter.json), [migration](preuves-apres/vault-migration.json), [conteneur Render local](preuves-apres/render-local/http-headers.json). ## Limites conservées

Cette correction est validée localement, pas sur le service Render distant, Neon ou le VPS. Les protections de déploiement, accès aux sauvegardes, secrets et procédures de récupération d’identité nécessitent leur propre contrôle d’exploitation. Aucun certificat de sécurité ou audit exhaustif n’est revendiqué.

La clé d’enveloppement des appareils est une donnée sensible de la base ; elle n’est pas chiffrée par une seconde clé applicative. Ne pas journaliser les réponses d’authentification ni `X-ALF-Vault-Key`. Les clés et mots de passe ne sont pas enregistrés en clair dans le coffre navigateur.

Un code/PIN court ne protège plus le coffre, mais un mot de passe initial faible malgré sa longueur reste vulnérable aux essais sur une copie du coffre. Une ancienne copie v2 ne peut pas être révoquée à distance ; migrer chaque appareil. Le contrôle du navigateur, une extension malveillante ou du code exécuté dans l’origine restent hors de la garantie cryptographique du cache local.

Les quotas réseau peuvent encore partager l’adresse d’un ingress de plateforme ; les quotas par compte évitent le regroupement de tous les utilisateurs dans une limite de connexion de 30/60 requêtes. L’IP publique finale de chaque visiteur Render n’a pas été vérifiée. Le limiteur en mémoire doit être partagé avant un déploiement à plusieurs instances, et les seuils doivent être qualifiés sur le trafic réel.
