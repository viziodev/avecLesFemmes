# Registre des décisions architecture

Les décisions ci-dessous reprennent le cadrage. Statut : proposé, appliqué au socle ; validation métier et exploitation avant production. Le choix de deux modes de connexion est confirmé par l’utilisateur le 14 octobre 2026.

| ADR                                      | Décision                                               | Conséquence et vérification                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 001                                      | Monolithe NestJS modulaire                             | Modules groupements, campagnes, cotisations, auth et base. Transactions locales.                                                                                                                                                                                                                                                                                                     |
| 002                                      | Base partagée isolée par groupement                    | RLS PostgreSQL et contrôles serveur ; contexte utilisateur SET LOCAL dans chaque transaction. Compte API sans SUPERUSER ni BYPASSRLS et non propriétaire. Fonctions d’accès SECURITY DEFINER à chemin de recherche fixé, seules habilitations explicitement accordées. Les migrations exigent un propriétaire capable de lire les tables protégées. Tests avec rôle applicatif réel. |
| 003                                      | PostgreSQL et montants exacts                          | BIGINT en FCFA ; API représente les montants stockés par chaînes pour éviter les pertes de précision ; entrées entières bornées. Index et pagination. Partitionnement après mesures.                                                                                                                                                                                                 |
| 004                                      | Compte, adhésion, participation et versement distincts | Forfait par participation ; anciennes cotisations inchangées ; modifications consignées dans l’audit.                                                                                                                                                                                                                                                                                |
| 005                                      | Cotisations transactionnelles et idempotentes          | Clé de saisie unique par groupement et empreinte du contenu. Verrou par campagne pendant la saisie. Annulation avec motif plutôt que suppression.                                                                                                                                                                                                                                    |
| 006                                      | Permissions par action et groupement                   | Super administrateur en consultation sauf groupements, types, membres et activation. Administratrice membre de son groupement. Vue personnelle pour membres.                                                                                                                                                                                                                         |
| 007                                      | Version des règles conservée par campagne              | Catalogue actuellement limité au moteur Avec. Version copiée à la création. Aucune édition rétroactive des règles.                                                                                                                                                                                                                                                                   |
| 008                                      | Tableaux de bord vérifiables                           | Calculs SQL indexés et sans cache dans le socle ; agrégats et workers selon mesures, sans obligation de Redis dès maintenant.                                                                                                                                                                                                                                                        |
| 009                                      | API sans état local et exploitation                    | Sessions PostgreSQL partagées. Santé, logs, sauvegardes et restauration à qualifier. Limitation des requêtes actuellement par instance ; stockage partagé du limiteur avant plusieurs instances.                                                                                                                                                                                     |
| 010                                      | Docker et Compose                                      | Images à plusieurs étapes, processus non privilégiés, bases figées par empreinte, secrets au lancement. Compose local et exemple production avec PostgreSQL externe. HTTPS ; recette Render puis production VPS Dokploy selon ADR 014.                                                                                                                                               |
| 011                                      | TypeScript et deux interfaces React                    | Un monorepo, UI et contrat client partagés ; validation serveur à l’exécution.                                                                                                                                                                                                                                                                                                       |
| 012                                      | Version commune et contrat API indépendant             | Produit évolutif (v0.1.0 à v0.1.3) ; API /api/v1 (v1.0.0) rétrocompatible ; migrations immuables avec checksum. Anciennes PWA supportées.                                                                                                                                                                                                                                            |
| 013                                      | Mot de passe et téléphone avec OTP                     | Sessions HttpOnly, SameSite, Secure en production ; scrypt pour mots de passe, codes expirant après cinq minutes et cinq tentatives, usage unique et délai de renvoi. Mode SMS local interdit en production. Adaptateur webhook à connecter au fournisseur choisi.                                                                                                                   |
| [014](014-deploiement-render-dokploy.md) | Recette Render puis production VPS Dokploy             | Promotion des mêmes images GHCR par empreinte, recette sur conteneur unique Render gratuit avec Neon (TLS vérifié, RLS), production VPS Dokploy avec base Neon dédiée, sauvegardes hors VPS et retour arrière qualifié.                                                                                                                                                              |

Le socle autorise une adhésion à plusieurs groupements, mais l’interface d’ajout crée de nouveaux comptes. Le rattachement d’un compte existant et la révocation de rôles restent à implémenter après validation. Le planning, les corrections fonctionnelles et les critères de lancement se trouvent dans [IMPLEMENTATION.md](../IMPLEMENTATION.md) et dans le document de cadrage.
